# FF-21d「孤立峰」判据的冲突裁定

**状态**：✅ 已裁定并落地（本仓实现依据）
**影响文件**：`app/lib/domain/service/behavior_analyzer.dart`
**相关文档**：`SPEC-P-07 §2.2 步骤 4`、`§7 判据 4/5`、`SPEC-00 §3.6 FF-21d`

---

## 1. 冲突

| 出处 | 原文 | 含义 |
|---|---|---|
| `SPEC-00 §3.6 FF-21d` | 「排除前后 300 ms 内无邻峰的孤立峰」 | 一个峰若在 ±300 ms 内找不到另一个峰，就丢弃 |
| `SPEC-P-07 §7 判据 4` | `isolatedPeak_removed`：前后无邻峰的峰被排除 | 同上 |
| `SPEC-P-07 §7 判据 5` | 合成「**每 0.7 s 一个峰**」→ `avgChewIntervalSeconds ≈ 0.7` 且 `speedGrade == '正常'` | 0.7 s 间隔的峰序列必须**全部保留** |
| `SPEC-00 §3.6 FF-21e` | 咀嚼间隔 `0.50–0.80 s` 为正常、`< 0.50 s` 偏快 | 真实咀嚼峰间距就是 0.5–0.8 s |

**按字面实现**：正常咀嚼的相邻峰相距 500–800 ms，**永远大于 300 ms**，因此每一个峰都会被判为
"孤立峰"并丢弃 → `chewCount == 0`、`avgChewIntervalSeconds == null`、`speedGrade == null`。
这条判据在**任何真实咀嚼录音上都会把行为分析清零**，同时使判据 4 与判据 5 无法同时成立。

这不是笔误，而是两条各自自洽的条款在组合后互斥 —— 与 `ADR-14`/`ADR-15`/`ADR-18` 同一类缺陷。

---

## 2. 裁定

**"孤立峰"是一个防单点误报的守门条件，不是咀嚼序列的过滤器。**

实现（`BehaviorAnalyzer.finish`）：

```
候选峰 = 高于动态阈值 μ + k·σ 的局部极大值
宽峰过滤：峰宽 > chew_max_peak_width_ms（150 ms）者剔除
孤立峰过滤：
    若 幸存峰数 >= 3  → 视为咀嚼序列，跳过邻域判定（序列中的峰按定义不孤立）
    否则（1–2 个峰）  → 按字面执行 ±300 ms 邻域判定，无邻峰者剔除
最小间距：相邻保留峰间隔 < chew_min_peak_distance_ms（200 ms）时保留幅值较大者
```

理由：
1. **保留判据的功能**：1–2 个孤立尖峰（关门声、碰撞声、麦克风爆音）仍会被剔除，
   `isolatedPeak_removed` 的意图完整保留。
2. **保住主用例**：≥3 个峰按定义为一段节奏序列，此时"孤立"不再有判别意义。
3. **两条判据同时可满足**：判据 4 用 1–2 个峰的夹具，判据 5 用 12 个峰的 0.7 s 序列。

## 3. 实测

`app/tool/pure_tests.dart` 的 `API-02 BehaviourAnalyzer` 组：

| 用例 | 期望 | 实测 |
|---|---|---|
| 12 峰 × 0.7 s（5 个 patch，共 30 个峰） | 检出且 `avgChewIntervalSeconds ≈ 0.7`、`正常` | ✅ `count=30`、`avg=0.6857`、`正常` |
| 12 峰 × 0.3 s | `偏快` | ✅ `偏快` |
| 单个孤立尖峰 | 剔除 → `finish()` 返回 `null` | ✅ `null` |
| 两个相距 5.2 s 的尖峰 | 均剔除 → `null` | ✅ `null` |
| 宽峰（> 150 ms 平台） | 剔除 → `null` | ✅ `null` |
| 全静音 | `null` | ✅ `null` |
