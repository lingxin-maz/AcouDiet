交叉评审查出的 19 条里，有 **6 条不是"文档写错了"，而是"在几个可行方案里选一个"**。这类裁定**不该由文档编写者单方面决定**，已单独抽出复核，**结论均为采纳原裁定**：

## 7. 文档使用规则（五条）

1. **数值只写一次**：一切参数引用 `SPEC-00` §3 的 FF 编号（如「见 FF-04」），**不要复制字面值**。复制就是漂移的开始。
2. **契约只写一次**：接口签名只在 `docs/*/docs_api/` 的 `API-0x` 里定义，其他文档引用编号。跨层冲突一律以接口层为准（ADR-10）。改了契约必须走 `API-00` §3.9 的变更流程。
3. **引用用编号，不用路径**：写 `SPEC-P-04`、`PLAN-C-03`、`API-03`；需要指整个契约目录时用 glob `docs/*/docs_api/`。**本次目录重组已经证明**：写路径的引用会随重组一起失效（当时共需改写 69 处）。
4. **JSON Schema 只有一个规范写法**：`docs/common/docs_api/schemas/<name>.schema.json`。曾经有三种写法并存，目录重组时只有一种被自动改写，另外 65 处静默失效 —— 这条是踩过坑才立的。
5. **验收必须可判**：写不出可执行判据的条目不许进 spec。允许的判据类型见 `SPEC-00` §7。
