# 后端设计文档索引（`docs/backend/`）

**定位**：设备内的 **L1–L4** —— 采集（Kotlin）、计算（域层）、存储（SQLite）、以及**离线训练管线**（Python）。
**规模**：**30 个功能**，分 6 个域，每个功能一个文件夹，内含它的 SPEC 与 PLAN。
**上游**：`docs/common/SPEC-00_总则与冻结事实.md`（下称 SPEC-00）—— **写任何文档或代码前必读**。
**总索引**：`docs/README.md` ｜ 冲突裁定：`docs/01_裁定记录ADR.md`

---

## 1. 先明确一件事：**核心链路完全离线，云端只是叠加的一层**

> 🔴 **本项目交付两个 Android 风味（`ADR-44`）。** `offline` 风味不申请 `INTERNET` 权限、不含任何网络调用（v1.0 姿态逐字节保留）；`agent` 风味申请 `INTERNET`，并在其之上叠加一个**默认关闭、需用户自备 API Key** 的云端智能体。
> `agent` 风味的全仓**恰好只有一个出网点**：`G-01` 的 `DeepSeekClient`（`API-05` §1 的 `R-OUT-4`）。崩溃上报 / 分析埋点 / SDK 遥测仍然禁止。
> **音频（PCM / Mel 张量 / 音频文件）在任何风味、任何版本下都不离开设备**（`FF-24` 第 8 条）—— 这是现行最强的那条隐私证据。

因此本文档里的"**后端**"首先指**运行在设备内的数据与计算平面**，它提供了传统后端的三项能力（**数据接入 / 数据存储 / 数据加工**），全部发生在设备内、不经过网络；`G_智能体与云端智能` 是唯一的例外，并且它只增加出口、不改变核心链路。

**完整裁定见 `API-05` §1（`ADR-44` 修订）与 §13，以及 `API-07`。**

## 2. 三层数据平面

```
┌──────────────────────────────────────────────────────────────┐
│ 采集平面 Native Data Plane            Kotlin（L1）            │
│   AudioRecord 16k/MONO/PCM16 → 环形缓冲 65536 样本            │
│   → VAD → 预处理 → Mel 前端 + RMS 包络                        │
│   → EventChannel 推送 patch 事件                              │
├──────────────────────────────────────────────────────────────┤
│ 持久平面 Local Persistence Plane      Dart + SQLite（L3）     │
│   diet_record / behavior_metrics / user_profile / app_meta    │
│   仅结构化字段，无 BLOB 音频；单文件 acoudiet.db              │
├──────────────────────────────────────────────────────────────┤
│ 分析平面 Analytics Plane              Dart 域层（L4）         │
│   推理 → 三级聚合 → 行为分析 → 知识库 → 评分 → 建议 → 周报    │
│   ⚠️ 评分必须是纯函数：同库同数据 → 同分数                     │
└──────────────────────────────────────────────────────────────┘
        ══════════ `offline` 边界：不存在任何网络接口 ══════════
        ══════════ `agent` 边界：`G-01` 的 `DeepSeekClient` 是唯一出口（`R-OUT-4`）══════════
```

**跨层规则**（`API-00` §1）：
1. L5 只能调 L4，**不得**直接调 L3 的 DAO，也不得直接调 L2 的 MethodChannel。
2. L4 不得 import Flutter widget（保持可单测）。
3. L3 不得包含业务规则（评分、建议、速度评级都属 L4）。
4. L1 不得包含 UI 文案与业务阈值（阈值来自 `feature_config`，经启动握手校验）。

```
D0 环境 + B 技能预演
      │
      ├─→ D2 Kotlin Mel 前端 (P-04) ─→ D3 Mel 对齐 (T-08) ─┐
      │                                                     ├─→ D5 端到端闭环 ★CP2
      └─→ D2 Baseline (T-04) ─→ D3 跨域评估 ★CP1 ──────────┤
                                        └─→ D4 TFLite (T-07)┘
                                                             ↓
                             D6 聚合 (P-06) ─→ D7 行为 (P-07) ─→ D8 闭环
                                                             ↓
```

**关键路径 = D0 → `P-04` → `T-08` → `T-07` → `P-05` → D5 闭环 → D9 Demo**

**B 是整个项目的单点故障**（`PLAN-00` §3.1）：`P-04`/`P-01`/`P-05`/`P-06`/`P-07`/`M-01`/`M-02` 全在他一条链上，不可并行、不可替代。

## 6. 不可交易的约束

| 约束 | 依据 |
|---|---|
| 音频**不落盘、不出设备** | FF-24 第 1 条 |
| 数据库**无 BLOB 音频列** | FF-24 第 3 条 |
| **音频在任何风味、任何版本下都不离开设备** | FF-24 第 8 条（`ADR-44` 新增，取代第 4 条成为最强主张） |
| **云端智能默认关闭**，须经显式同意门才可开启 | FF-24 第 9 条（`ADR-44` 新增） |
| `offline` **不申请 `INTERNET`、无任何网络调用**；`agent` 恰多一项 `INTERNET`，出口唯一 | FF-24 第 4 条（`ADR-44` 修订）/ `R-OUT-4` |
| 权限集合：`offline` **不申请**（恰 `{RECORD_AUDIO}`）、`agent` **申请**（恰 `{RECORD_AUDIO, INTERNET}`），无后台常驻 Service | FF-24 第 5/6 条 |
| Mel 参数**两侧同源**（都读 `feature_config`） | FF-08 / `C-03` |
| 评分**可复现**（禁用"当前时间"作判据） | `API-05` §6.1 |

## 7. 已裁定的三处设计缺陷（**动手前必读，否则会踩已修好的坑**）

| ADR | 问题 | 结论 |
|---|---|---|
| `ADR-01` | `P-07` **没有数据源**（patch 事件原只带 mel/rms/voiced） | 包络计算下沉 Kotlin（FF-21h/i），峰值判定留 Dart |
| `ADR-02` | `M-02` 恰在**麦克风故障时失效**（`startSession` 必然初始化 `AudioRecord`） | 新增 `skipAudioRecord` |
| `ADR-09` | 原餐次窗口使 `snack` 维度**恒满分、失去区分度** | 窗口改为 早`[05,10)`/午`[11,14)`/晚`[17,21)` |

完整 19 条见 `docs/01_裁定记录ADR.md`。
