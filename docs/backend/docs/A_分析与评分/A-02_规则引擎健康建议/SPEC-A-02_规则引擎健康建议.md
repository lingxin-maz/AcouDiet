## 1. 目标与范围

### 1.1 一句话目标

把 `HealthScore` 与窗口聚合（`WeekSummary`）按**五条固定规则**映射为**确定性、可解释、不触碰宣传口径红线**的建议列表（`Advice`），并保证**免责声明项恒存在且恒在末位**、数据不足时不编造建议。

### 1.2 范围内（In Scope）

- 五个规则维度：**零食频率、晚间进食、进食速度、饮食规律性、食物多样性**（映射到 `API-04 §4` 的 `dimension` 枚举，见 §5 表 A-02-T1）。
- 每条建议含 `dimension` / `text` / `priority`（`API-04 §4`）。
- **免责声明项**：`dimension == 'general'`、`priority` 取全表最大值（排最后）、**不因数据不足而省略**（`API-04 §4`）。
- 免责声明文案冻结（§5 A-02-K6）：**「提供日常健康管理建议，不进行疾病诊断，不替代专业医疗意见」**。
- 确定性排序（`priority` → `dimension` 固定序 → 规则表声明序）与条数上限（§5 A-02-K1）；同输入 100 次输出逐字相同。
- 数据不足 → 返回**恰含 1 条 `general` 项**的列表（§2.4 #1、§6）。

### 1.3 范围外（Out of Scope）——必须显式写出，防止实现方自由发挥

- **不重算分数**：四维分与总分一律取自 `SPEC-A-01` 的 `HealthScore`；本域不得出现 FF-22 的四维公式。
- **不写 SQL、不做聚合**：`snackCount` / `lateNightCount` / `classCounts` 取自 `StatsRepo`（`SPEC-D-03`、`API-03 §5`）；窗口边界口径权威在 `API-03 §5`，本域只消费。
- 不做环比百分比文案（属 `SPEC-A-03` 的 `summaryText`）；本域文案中的数字只能来自 `HealthScore`/`WeekSummary` 已有字段。
- 不展示咀嚼次数与咀嚼节律（`FF-21f` 的「约」规则、`FF-21g` 的 MAE 降级属 `P-07`/`U-02`/`U-03` 的展示域；本域的速度规则只用**平均咀嚼间隔**，故 `FF-21g` 在本功能内不触发）。
- 不做疾病诊断、不做用药/就医/治疗方案建议（只提供日常健康管理建议）。
- 不接入 LLM 或任何网络服务（`FF-24` 第 4 条；`API-05 §9` 状态 `DISABLED`，不得作为任务来源）。
- 不使用咀嚼节律 σ（`X-07`）、不支持手工改类别（`X-02`）、不导出建议（`X-03`）。
- **不得新增 `dimension` 枚举值**（schema `enum` 仅 `regularity`/`structure`/`snack`/`speed`/`general`）。

## 2. 功能行为

### 2.1 触发与前置条件

| # | 前置条件 | 来源 |
|---|---|---|
| 1 | 同一窗口的 `HealthScore` 已算出（`SPEC-A-01`） | `API-04 §3` |
| 2 | 同一窗口的 `WeekSummary` 已取得（`recordCount`/`snackCount`/`lateNightCount`/`classCounts`） | `API-03 §5` |
| 3 | 有效数据集已确定（演示模式下聚合只含 `source == 'demo'`） | `SPEC-A-04` |
| 4 | 免责声明文案以编译期常量提供（非运行时拼接） | §5 A-02-K6 |

### 2.2 主流程（编号步骤）

1. 建立 `general` 免责声明项：`dimension = 'general'`、`text = A-02-K6`、`priority = A-02-K2 的最大值`。**先入列**，保证任何分支都不会漏。
2. **不足判定**：`agg.recordCount < A-02-K4` → 直接返回仅含该 `general` 项的列表（§2.4 #1）。
3. 依次评估五条规则（条件、模板、优先级见 §5 表 A-02-T1）；命中则按模板填充**真实字段值**生成 `Advice`。
4. 填充规则：占位符只允许来自 §4 白名单；所需字段为 `null` → **跳过该条规则**（不得用 0 冒充、不得留空占位符）。
5. 排序：`priority` 升序 → 同 `priority` 按 `dimension` 固定序（`regularity → structure → snack → speed → general`，`API-04 §4`）→ 同二者按表 A-02-T1 的声明序（稳定排序，禁止随机）。
6. 截断：非 `general` 建议最多 A-02-K1 条；**`general` 项永不被截断**，恒在末位。
7. 返回 `List<Advice>`。全过程无随机、无系统时钟读取、无 IO、无网络。

### 2.3 状态与状态迁移（有状态的功能必填，无状态写「无状态」）

**无状态**。`AdviceEngine` 不缓存上次结果；同一入参重复调用返回逐字相同列表。

### 2.4 边界条件

| # | 场景 | 处理（确定性） |
|---|---|---|
| 1 | `recordCount < 3`（A-02-K4） | 返回**恰 1 条** `general` 项；`U-04` 在无 `general` 以外的建议时展示「暂不生成建议」+ 免责声明 |
| 2 | 五条规则全部未命中 | 返回**恰 1 条** `general` 项（同上，不编造建议） |
| 3 | 命中条数 > A-02-K1 | 按 §2.2 第 5、6 步截断（**不是**随机丢弃），`general` 项保留 |
| 4 | 单字段为 `null`（如 `sigmaMinutes == null`） | 跳过依赖该字段的规则，其余规则照常 |
| 5 | `classCounts` 某键缺失 | `API-03 §5` 保证 6 键齐全（缺失补 0）；本域按缺 0 处理，不抛错 |
| 6 | 演示数据集生效 | 建议照常生成；`U-04` 必须同时显示「演示数据」标识（`SPEC-A-04`） |
| 7 | 4 类降级模式（`FF-19` 降级开关生效） | 多样性规则的分母改为当前生效类别数（`classCounts` 键数）；文案不出现具体类别数以外的数字 |

## 3. 接口契约

> 只写与本功能直接相关的契约；完整签名以 `docs/*/docs_api/` 为准，此处给「本功能用到的部分」并标注 API 编号。

| 方向 | 接口 | 输入 | 输出 | 错误码 |
|---|---|---|---|---|
| L5 → L4 | `AdviceEngine.generate` | `{required HealthScore score, required WeekSummary agg}` | `Future<List<Advice>>` | `ACD-SCORE-001`（`score` 为残缺对象）/ `ACD-KB-001`（引用知识库文案时未加载） |
| L4 → L3 | `StatsRepo.week()` | — | `WeekSummary` | `ACD-DB-003` `ACD-DB-004` 透传不吞 |
| L4 → L5 | `Advice` | — | `{String dimension, String text, int priority}` | — |

- 返回类型为 `Future` 仅为与 `API-04 §4` 签名一致；**实现必须是同步纯计算**，不得引入延时、定时器或 IO。
- 免责声明**以 `general` 项形式进入列表**（`API-04 §4` 强制「恰好一条 + `priority` 最大 + 排最后」），因此 `advices` **永不为空列表**；`U-04` 据此渲染常驻免责声明（`SPEC-U-04 §2.4`）。
- 权威归属：`Advice` 字段与 `dimension` 枚举以 `API-04 §4` + `health_score.schema.json` 为准；本 SPEC 只补充规则、阈值与文案。

## 4. 数据契约

> 涉及的字段、类型、单位、值域、可空性。引用 `docs/common/docs_api/schemas/` 中的 schema 文件名。

- **输出结构**：`docs/common/docs_api/schemas/health_score.schema.json` 的 `advice` 子模式（`additionalProperties: false`；`dimension` 枚举五值；`priority` 整数 `≥1`）。
- **`text` 约束**：中文；≤ A-02-K11 字；不含 `FF-25` 禁用表述；不含诊断/治疗语句；不含孤立精确热量数字。
- **输入字段白名单（占位符唯一合法来源）**

| 占位符 | 语义 | 权威字段 |
|---|---|---|
| `{n}` | 本周零食次数 | `WeekSummary.snackCount`（`API-03 §5`） |
| `{m}` | 本周晚间进食次数（`[20:00, 05:00)`） | `WeekSummary.lateNightCount`（`API-03 §5`） |
| `{t}` | 本周平均咀嚼间隔（秒，1 位小数） | `HealthScore.speed.evidence['avgChewIntervalSeconds']` |
| `{k}` | 本周出现过的类别数 | `classCounts` 中值 > 0 的键数 |
| `{N}` | 本周记录总数 | `WeekSummary.recordCount` |

> **窗口唯一权威是 `API-03` §5（`ADR-09`）**：本 SPEC **不复制边界值** —— 上表列出的 `[20:00, 05:00)` 仅为可读性；任何窗口改动一律以 `API-03` §5 为准，并走 `PLAN-C-03` 变更传播。

- **免责声明文案（逐字，不得改写、不得翻译、不得增删标点）**：由 §5 A-02-K6 冻结，并作为 `dimension == 'general'` 项的唯一文本。
- `general` 项的 `priority` = A-02-K2 的最大值；任何建议项的 `priority` 必须严格小于它。

**表 A-02-T1 五条规则（条件、模板与优先级的权威定义）**

| # | 规则维度（业务名） | `dimension` | 触发条件 | 文案模板（填充后 ≤ 40 字） | `priority` |
|---|---|---|---|---|---|
| 1 | 零食频率 | `snack` | `{n} ≥ A-02-K7` | `本周零食 {n} 次，建议减少薯片与软糖的频率，两餐之间可优先选择卷心菜或胡萝卜。` | 1 |
| 2 | 晚间进食 | `regularity` | `{m} ≥ A-02-K8` | `有 {m} 次进食发生在晚间，建议把正餐与加餐安排得更早一些。` | 1 |
| 3 | 进食速度 | `speed` | `{t} < FF-21e 的「偏快」阈值` | `本周平均咀嚼间隔约 {t} 秒（偏快），建议放慢进食节奏。` | 2 |
| 4 | 饮食规律性 | `regularity` | `sigmaMinutes != null` 且 `score.regularity.score < A-02-K9 × max` | `三餐时间不够固定，建议固定每天的用餐时段。` | 2 |
| 5 | 食物多样性 | `structure` | `{k} ≤ A-02-K10` | `本周记录到的食物只有 {k} 类，建议主食与蔬果类都出现一些。` | 3 |
| — | 免责声明 | `general` | **恒命中** | A-02-K6 文案（逐字） | A-02-K2 最大值 |

## 6. 异常与降级

| 异常 | 检测方式 | 处理 | 用户可见表现 |
|---|---|---|---|
| 数据不足（`recordCount < 3`） | 计数判定 | 返回仅含 `general` 项的列表 | 「暂不生成建议」+ 免责声明（`U-04`） |
| 规则全部未命中 | 评估后仅剩 `general` 项 | 同上 | 同上 |
| 依赖字段为 `null` | 字段判空 | 跳过该规则 | 少一条建议，不报错、不留占位符 |
| 生成的文案超长或残留 `{x}` | 长度/正则断言 | 视为**实现缺陷**，构建期测试失败 | 不进入现场 |
| `score` 为残缺对象 | 前置校验 | 抛 `ACD-SCORE-001` | 页面错误态 |
| 知识库未加载（引用 `riskNote` 时） | `ACD-KB-001` | 透传不吞 | 页面错误态 |
| 读取 `WeekSummary` 失败 | `ACD-DB-003` | 透传不吞 | 页面错误态 + 重试入口 |

## 8. 非功能约束

> 性能 / 内存 / 功耗 / 隐私 / 无障碍，只写与本功能相关的。

- **性能**：Dart 主 isolate 内的纯计算（`API-00 §3.7`），输入为窗口级聚合对象；耗时为**实测产出**，本 SPEC 不预设数字。
- **内存 / 功耗**：无 IO、无网络、无后台任务（`FF-24` 第 6 条：无后台常驻 Service）。
- **隐私**：只读结构化字段；文案不含可识别个人信息；不接触音频（`FF-24`）。
- **无障碍**：`priority` 不得只用颜色表达，`U-04` 必须以排序与文字体现；文案为纯文本，读屏可读；免责声明必须可被读屏朗读。
