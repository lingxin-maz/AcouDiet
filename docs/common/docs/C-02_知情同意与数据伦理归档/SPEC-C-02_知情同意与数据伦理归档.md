## 1. 目标与范围

### 1.1 一句话目标

在**任何志愿者音频进入仓库之前**完成书面知情同意、匿名编号与归档，使自采数据在伦理上「先签后用、可撤回、可举证、可附卷提交」。

### 1.2 范围内（In Scope）

| # | 内容 | 产物（路径级） |
|---|---|---|
| 1 | 知情同意书模板（必含 §4.1 的 7 条） | `docs/compliance/C-02/consent_form_v1.0.md` |
| 2 | 签署件扫描归档（**姓名打码**） | `docs/compliance/C-02/scans/<subjectId>_consent_masked.pdf` |
| 3 | 志愿者归档清单（编号 / 段数 / 类别覆盖 / 采集日期 / 同意书路径） | `docs/compliance/C-02/consent_registry.md` |
| 4 | 撤回权执行记录（请求时间、删除范围、完成确认） | `docs/compliance/C-02/withdraw_log.md` |
| 5 | 招募 5–10 名志愿者；**先签后用**（未签不使用其数据，风险 R-11） | 签署件数 ≥3（D1 结束最低线） |
| 6 | R-7 兜底：D1 结束仍 <3 名志愿者 → 组内成员自录，**仍需签同意书** | 归档清单中标注数据来源为组内自录 |
| 7 | 提交竞赛材料时附上已签署扫描件（姓名打码）；并登记 `API-05` §11 可携带性缺口 | 材料清单第 1 项；本文档 §10 #1 |

## 2. 功能行为

### 2.1 触发与前置条件

| 项 | 要求 |
|---|---|
| 触发时机 | **D0 当日启动**（主方案 §6.2、`PLAN-00` D0「`C-02` 招募与同意书」） |
| 硬前置 | 志愿者音频进入 `ai/data/raw/` **之前**必须已签署；违反即触发 R-11 处置（该志愿者数据全部不使用并删除） |
| 前置 | 6 类冻结类别清单（`SPEC-00` §3.3 FF-19）与自采规模目标（主方案 §7.1）已明确，用于向志愿者说明采集内容；打印件一式两份 |

### 2.2 主流程（编号步骤）

1. 打印 `consent_form_v1.0.md` 两份；同时准备空白志愿者编号表。
2. 逐条口头讲解 §4.1 的 7 条内容并答疑；向志愿者说明**不采集人声对话内容**与**随时可撤回**。
3. 志愿者签署（手写签名 + 日期）；项目组签署人同页签署。
4. 分配匿名编号 `P<两位序号>`（格式见 `API-00` §3.4），**编号一经分配不再复用、不再改写**。
5. 扫描签署件，对姓名与联系方式区域**打码**，落到 `docs/compliance/C-02/scans/`。
6. 在 `consent_registry.md` 登记一行（字段见 §4.2），登记完成后方可开始采集。
7. 采集按 `ai/data/raw/<subjectId>/<yyyymmdd>_<class>_<seq>.wav` 命名（`subjectId` 即 `P0x`）；提交竞赛材料时把打码扫描件作为附录第 1 项。

### 2.3 状态与状态迁移

志愿者数据的治理状态机（**有状态**）：

```
RECRUITED ──签署──▶ CONSENTED ──采集──▶ COLLECTED ──入库──▶ IN_DATASET
                        │                    │                   │
                        └────────撤回请求────┴───────────────────┘
                                     ▼
                                 WITHDRAWN ──删除执行+确认──▶ DELETED
```

| 状态 | 含义 | 允许的下一状态 |
|---|---|---|
| `RECRUITED` | 已接触、未签署 | `CONSENTED`、`DROPPED` |
| `CONSENTED` | 已签署并归档（**唯一可采集状态**） | `COLLECTED`、`WITHDRAWN` |
| `COLLECTED` / `IN_DATASET` | 已有音频（未入划分 / 已入划分） | `WITHDRAWN` |
| `WITHDRAWN` | 已收到撤回请求 | `DELETED` |
| `DELETED` | 原始数据已删除、划分已剔除、已书面确认 | 终态 |
| `DROPPED` | 未签署即退出 | 终态（无数据） |

### 2.4 边界条件

- **未签署 = 不可使用**（R-11 的唯一处置）；「口头同意」不成立。
- **撤回的删除范围**：① `ai/data/raw/<subjectId>/` 全部音频；② 该编号在 `splits/*.csv` 中的所有行；③ 派生特征缓存；④ `consent_registry.md` 中标注 `DELETED` 与日期。
- **撤回与已训练权重的处置（v1.0 明确取舍）**：本期**不因单次撤回重训**权重；处置是「删除原始数据 + 剔除划分 + 书面确认」，并在 `withdraw_log.md` 记录「下一版重训时该编号数据不计入」。此为**已知限制**，见 §10 #3。
- **人声处理**：录音若含对话，在标注阶段剔除该片段；剔除不改变编号、不改变已签署范围；剔除计数登记入归档清单。
- **R-7 兜底**：D1 结束仍 <3 名志愿者 → 组内成员自录（**本人即为数据主体，仍需签署同意书**）；若仍不足，在 §10 登记并下调自采规模，**不得用未签数据凑数**。
- 志愿者要求「匿名展示」时，所有对外材料只用编号，不出现姓名与联系方式。

## 3. 接口契约

本功能**不产生运行时接口**（纯流程与文档），但它是下游数据契约的**准入约束**：

| 方向 | 接口 | 输入 | 输出 | 错误码 |
|---|---|---|---|---|
| 数据准入（文档级） | `SPEC-T-01` 数据集入库 | `subject_id`（`P<两位序号>`） | 仅接受 `CONSENTED` 及以上状态的编号 | 未签编号 → 拒绝入库并登记 R-11 |
| 数据准入（文档级） | `SPEC-T-02` 划分 | `splits/*.csv` 的 `subject_id` 列 | 不含 `WITHDRAWN`/`DELETED` 编号 | 命中即判不通过 |

## 4. 数据契约

### 4.1 知情同意书必含 7 条（逐字对应主方案 §6.2）

| # | 条款 | 要点（同意书正文须逐条对应） |
|---|---|---|
| 1 | 数据用途 | 仅用于本项目声学模型训练，不用于任何其他目的 |
| 2 | 采集内容 | 进食过程音频（**不采集人声对话内容**） |
| 3 | 存储位置 | 仅存于项目组本地设备（无云端、无网络出口，`API-05` §1） |
| 4 | 匿名化 | 以 `P01/P02…` 编号标识，不记录姓名/联系方式（`API-00` §3.4） |
| 5 | **撤回权** | 志愿者可随时要求删除其全部数据 |
| 6 | **不留存人声** | 录音中若含对话，标注阶段予以剔除 |
| 7 | 不对外发布 | 数据不对外发布；若需发布另行取得授权 |

### 4.2 归档清单字段（`consent_registry.md`）

| 字段 | 类型 | 值域 | 可空 |
|---|---|---|---|
| `subjectId` | string | `P01`…`P10` | 否 |
| `signedDate` | string | `yyyy-MM-dd` | 否 |
| `scopeVersion` | string | 同意书模板版本（如 `v1.0`） | 否 |
| `sourceType` | enum | `volunteer` / `team_member`（R-7 兜底） | 否 |
| `segmentCount` | int | `≥0` | 否 |
| `consentScanPath` | string | `docs/compliance/C-02/scans/...` | 否 |
| `voiceRemovedCount` | int | `≥0`（剔除的人声片段数） | 否 |
| `status` | enum | §2.3 的状态枚举 | 否 |
| `withdrawnAtMs` | int64 | epoch 毫秒（UTC，`API-00` §3.2） | 是 |

> **无对应 `docs/common/docs_api/schemas/*.schema.json`**：本功能不新增 schema 文件；建议后续补机器可读版本。**模板路径冲突提示**：主方案 §5.1 的仓库结构写有 `docs/05_伦理与知情同意.md`，本文档以 `docs/compliance/C-02/` 为唯一权威位置，二者关系见 §10 #4。

## 6. 异常与降级

| 异常 | 检测方式 | 处理 | 用户可见表现 |
|---|---|---|---|
| D1 结束志愿者 <3 名（R-7） | 归档清单行数 | 启用组内成员自录，仍需签同意书；在清单标注 `sourceType=team_member` | 无 |
| 收到撤回请求 | 口头/书面请求 | 进入 `WITHDRAWN` → 执行 §2.4 删除范围 → 书面确认 → `withdraw_log.md` 记录 | 无（对数据主体须给确认回复） |
| 同意书缺项或涂改 | 归档审查 | 重新签署；不补签、不代签 | 无 |
| 采集时录到人声对话 | 标注阶段试听 | 剔除该片段并计入 `voiceRemovedCount` | 无 |
| 未签署数据已误入库 | `SPEC-T-02` 划分检查 | 立即删除该 `subject_id` 全部数据并记入 `withdraw_log.md` | 无 |

## 8. 非功能约束

| 项 | 约束 |
|---|---|
| 隐私 | 同意书第 1/3/6 条与 FF-24 必须逐条一致；不得承诺超出 v1.0 能力的数据保护（如「加密存储」，`API-05` §5.7 明确不做） |
| 合规 | 必须如实声明 `API-05` §11 的可携带性缺口，**不得自称「完全合规」** |
| 可追溯 | 每个编号都能从清单追到扫描件、从扫描件追到采集目录 |
| 脱敏 | 归档件必须打码；打码前原件不得进入仓库 |

## 9. 裁剪与未做

| 项 | 决定 | 依据 |
|---|---|---|
| CSV / 数据导出（数据主体获取自身信息的途径） | ❌ 不交付 → 同意书第 5 条的「撤回」可实现，但**「获取」途径缺失** | `X-03`、`API-05` §11 |
| 正式 IRB / 伦理委员会报批 | ❌ v1.0 不做（窗口外流程） | §10 #2 |
| 数据脱敏自动化 | ❌ 人工打码 | 本 SPEC §1.3 |
| 撤回后自动重训 | ❌ 不交付（成本不可接受） | 本 SPEC §2.4、§10 #3 |
