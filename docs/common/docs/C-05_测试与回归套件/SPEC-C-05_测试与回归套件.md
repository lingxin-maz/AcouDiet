## 1. 目标与范围

### 1.1 一句话目标

用一套分层、可重复、跑得出退出码的测试与回归套件，把「评分卡数字与 UI 一致」「数据划分无泄漏」「Python/Kotlin 数值对齐」「隐私约束不回退」「演示前逐项可核对」这五件事变成每次提交都能自动判定的事实。

### 1.2 范围内（In Scope）

| # | 内容 |
|---|---|
| 1 | **跨功能一致性测试**：评分卡数字 == UI 显示数字（`API-05` §6.1、主方案 §9.1；防风险 R-10），覆盖 Track 1/Track 2 双轨 |
| 2 | **数据划分无泄漏断言**：`SPEC-T-02` 的机器可检版本（主体级交集为空、已撤回编号剔除） |
| 3 | **数值对齐测试**：`SPEC-T-08` 的调度与门禁（parity + Mel 跨语言 + 内存布局） |
| 4 | **隐私回归**：临时音频清理计数为 0、无 BLOB 列、无网络权限 |
| 5 | **演示前回归清单**与**演示前 30 分钟检查清单**（对应主方案 §9.2 现场 SOP）；测试文件命名规范与目录约定（`app/test/`、`app/integration_test/`、`ai/scripts/`） |

### 1.3 范围外（Out of Scope）

| 不做 | 归属 |
|---|---|
| 被测功能本身的实现 | 各功能对应 SPEC |
| 跨域准确率指标产出、训练/量化/导出、CI/CD 流水线、覆盖率门禁、性能压测、全页面 UI 自动化 | `SPEC-T-05`、`SPEC-T-04`、`SPEC-T-07`；其余 ❌ v1.0 不做（性能数字禁止编造；UI 只覆盖关键路径冒烟） |

## 2. 功能行为

### 2.1 触发与前置条件

| 触发 | 集合 | 前置 |
|---|---|---|
| 每次提交前 | 快集合（Dart 单元 + pytest 单测 + 命令级搜索） | 环境已激活；`flutter test`/`pytest` 可在**沙箱外普通终端**执行 |
| D1 | 划分无泄漏断言 | `splits/*.csv` 已生成 |
| D3 / D4 | Mel 跨语言对齐（**硬闸门**）、parity 门禁 + 权限复核 | `SPEC-P-04` 产出 `[128, n_frames]` 数组；`SPEC-T-07` 产出**按卡片申报档位**的 TFLite（fp32 / int8 两档都可交付，`ADR-21`） |
| D5 / D8 / D9 前 | 一致性、事务、清理（含真机隐私回归）；D9 前跑全集合 + 附表 A + 附表 B | 真实数据可写入、真机可用、三种 Demo 模式可用 |

### 2.2 主流程（编号步骤）

1. **分层**：Dart 单元（`app/test/`）→ 真机仪器（`app/integration_test/`）→ 离线脚本（`ai/scripts/`）→ 命令级检查（`rg`/`aapt`/`sqlite3`）→ 人工核对表。
2. **五类必须覆盖**：① 跨功能一致性（逐字段等于 UI 值，不是"接近"）；② 划分无泄漏（主体级 + 撤回剔除）；③ 数值对齐（Python↔Kotlin Mel、Keras/PT↔TFLite）；④ 隐私回归（清理计数 0、无 BLOB、无网络权限）；⑤ 演示前回归（附表 A/B）。
3. **运行矩阵与阻塞语义**：提交前只跑快集合、节点日跑全集合（见 `PLAN-C-05` §3）；任一断言失败不提交、不进节点验收，**禁止用 `skip:` 绕过**（必须跳过时须在文件内注明原因并登记 §10）。
4. **取证**：全集合输出写入 `docs/compliance/C-05/`，作为 D10 材料的一部分。

### 2.3 状态与状态迁移

**无状态**：测试套件不维护运行时状态，每个测试独立可重跑，且必须能在干净检出上复现（不依赖上次运行的产物）。唯一例外是**门禁状态**（由测试报告判读承担）：

| 状态 | 含义 | 允许的下一状态 |
|---|---|---|
| `GATE_PENDING` | 节点日测试未跑 | `GATE_PASS`、`GATE_FAIL` |
| `GATE_PASS` | 该节点全部断言通过且输出已归档 | 终态（至下次改动） |
| `GATE_FAIL` | 存在失败断言 | `GATE_PENDING`（修复后重跑） |

### 2.4 边界条件

- **一致性测试必须针对「当前生效数据集」**（Track 1 真实累积或 Track 2 预置，`SPEC-A-04`），不得写死 fixture 之外的假设。
- **阈值不得自行放宽**：`SPEC-00` §7 的合格示例为「标签一致率 ≥0.98、最大置信度偏差 ≤0.05」；`PLAN-00` D3 的 Mel 门禁为 `atol < 1e-3`。放宽须走 `SPEC-C-03` 变更流程。
- **隐私回归必须在真机至少跑一次**（`cacheDir` 行为与设备相关）；评分服务必须是纯函数（`API-05` §6.1），断言两次运行逐字段相等且不依赖当前时间。
- **套件内不得发起网络请求**（`API-05` §1）；测试代码不得复制 SSOT 字面值（一律引用生成常量或 `SPEC-00` 编号，防 R-20）；附表 A/B 是人工项，必须给逐项核对表。

## 3. 接口契约

| 方向 | 命令 | 输入 | 输出 | 失败语义 |
|---|---|---|---|---|
| 单元测试 | `flutter test` | `app/test/**` | 通过/失败计数 | 任一失败 → 非 0 退出码，阻塞提交 |
| 单文件 / 仪器 | `flutter test app/test/<层>/<文件>_test.dart`；`flutter test integration_test/<场景>_test.dart` | 指定文件 / 真机 | 同上 | 同上 |
| Python 侧 | `python -m pytest ai/scripts -q` | `ai/scripts/test_*.py` | 同上 | 同上 |
| 命令级 / 静默回退契约 | `rg`、`aapt dump badging`、`sqlite3`；TFLite 委托失败（`ACD-INF-003`） | APK / DB / — | 文本；断言**不抛给 UI**、静默回退 CPU | 命中数不符、或抛异常 → 判不通过 |

## 4. 数据契约

### 4.1 测试文件命名规范与目录

| 目录 | 用途 | 命名规范 | 子结构 |
|---|---|---|---|
| `app/test/`、`app/integration_test/` | Dart 单元/widget 测试、真机仪器测试 | `<被测对象>_test.dart` / `<场景>_test.dart`（lower_snake_case） | `domain/`、`data/`、`cfg/`、`ui/`；端到端闭环、清理计数、自检面板 |
| `ai/scripts/` | 离线脚本与 Python 测试 | `test_<对象>.py`（pytest 可发现） | 划分、形状、parity、Mel 对齐 |
| `docs/compliance/C-05/` | 测试取证输出 | `<节点>_<YYYYMMDD>_<套件>.txt` | 全集合输出与判读结论 |

**命名硬规则**：①只用小写字母、数字、下划线；②测试名必须描述断言（`expect(actual, equals(expected))`），禁止 `test1`；③同一断言不得在两处重复实现。

### 4.2 测试报告字段（每次全集合运行一份）

| 字段 | 类型 | 值域/约束 |
|---|---|---|
| `runAtMs` / `node` | int64 / enum | epoch 毫秒（UTC，`API-00` §3.2） / `precommit` `D1` `D3` `D4` `D5` `D8` `D9` |
| `passed` / `failed` / `skipped` / `artifacts` / `gate` | int / string[] / enum | `≥0`（放行要求 `failed == 0`，`skipped` 非 0 须登记原因）；证据文件路径（可空）；§2.3 的门禁状态 |

## 6. 异常与降级

| 异常 | 检测方式 | 处理 |
|---|---|---|
| 断言失败 / 测试不稳定 | 退出码非 0；同命令连跑 3 次结果不一致 | 阻塞提交与节点验收，修复后重跑；不稳定属缺陷，须定位时间依赖/随机种子/并发，**不得靠重跑掩盖** |
| 无可用真机 | `flutter devices` 为空 | 降级为单元 + 命令级；报告标注仪器项未跑；**真机隐私回归不得缺席 D9** |
| 一致性测试与 UI 不一致（**R-10**） | 判据 #2 失败 | **冻结 UI、修复数据或评分服务**；不得改断言 |
| 对齐阈值超界 / 旧值残留命中 | 判据 #4 超界；命令输出非空 | 按 `SPEC-T-08` 定位（内存布局、归一化、边界帧）；旧值逐条修正后重跑（授权例外仅 `SPEC-C-03` §7 #3 的两处历史对比表） |

## 8. 非功能约束

| 项 | 约束 |
|---|---|
| 可重复与时长 | 干净检出可复现同一结果；提交前快集合必须能在站会间隔内跑完，否则开发者会绕过它 |
| 无网络 | 套件内不得发起任何网络请求（`API-05` §1） |
| 数值口径与隐私 | 阈值引用权威文档，不复制可能漂移的字面值（防 R-20）；测试不得把真实用户音频写入仓库，夹具须来自公共集或有同意书的自采 |

| 项 | 决定 |
|---|---|
| CI/CD 流水线、覆盖率门禁 | ❌ 不交付/不设（人工执行矩阵 + 报告归档；只做本 SPEC 列出的断言） |
