# 前端设计文档索引（`docs/frontend/`）

**定位**：表现层 **L5** —— 用户**看得见、点得到**的一切。Flutter 3.24.5 + Dart 3.5.4 + Riverpod + `fl_chart`。
**规模**：**9 个功能**（7 个页面/组件 + 2 个演示界面），每个功能一个文件夹，内含它的 SPEC 与 PLAN。
**上游**：`docs/common/SPEC-00_总则与冻结事实.md`（下称 SPEC-00）—— **写任何文档或代码前必读**。
**总索引**：`docs/README.md` ｜ 冲突裁定：`docs/01_裁定记录ADR.md`

## 1. 为什么"前端"在这个项目里只有 9 个功能

本项目的核心链路是**端侧单机 App**：检测、记录、报告全部离线（见 `API-05` §1 的 `ADR-44` 修订）。`ADR-44` 额外交付了一个云端智能体，它在前端只增加**一个页面**（`U-07`），且该页**默认关闭**。因此传统意义上的"前端"仍然只是：**把后端算好的数渲染出来 + 收集用户的一次性输入**。

前端**不做**：不算 Mel、不跑推理、不查数据库、不做评分。所有数字都从域服务拿（见 §4 数据来源链）。
**这条边界是硬性的**：L5 只能调 L4 域服务（`API-04`），**不得直接调 L3 的 DAO**，也不得直接调 L2 的 MethodChannel（`API-00` §1 规则 1）。

> `智能体页` 的四行只在 **`agent` 风味**存在；`offline` 风味**不构建**该页（`FF-24` 第 4 条）。该页**不允许**出现音频数值、`cacheDir` 路径、设备标识或 API Key 明文（`FF-26e`）。

**记录条目标准模板**（消除设计稿的粒度失控）：

```
┌────────────────────────────────────────────┐
│ 12:20  面条                    ≈120 kcal   │
│        软性主食 · 1 片（估算）              │
│        置信度 88%                      ›   │
└────────────────────────────────────────────┘
```

### 三条硬规则

1. **热量数字必须带份量描述与「估算」字样**，禁止孤立出现 `120 kcal`。
2. **食物粒度必须落在 6 类内**（chips 薯片 / cabbage 卷心菜 / gummies 软糖 / noodles 面条 / carrot 胡萝卜 / drink 饮料）。禁止「全麦面条」「纯牛奶」「番茄」「鸡翅」等超出识别粒度的命名（ADR-19 起「面条」本身是正式类别，不再是禁用词）。
3. **无法从模型推导的营养素（蛋白质/脂肪/碳水/膳食纤维）一律不得出现在 UI 上。**

### 时间口径

`从开始进食到首次确认结果约 4–5 秒`（1 个 patch 4.096 s + 2.0 s 稳定判据）。**这是窗口长度的必然结果，不是缺陷；任何材料不得承诺「2 秒内出结果」。**

## 4. 数据来源链（前端只读、只渲染）

```
页面 (U-01…U-06)
   │  只调 L4 域服务
   ▼
API-04 域服务 ──── HealthScoreService / AdviceEngine / ReportService
   │               FoodKnowledgeBase / DemoController / DemoDataController
   ▼
API-03 数据访问层 ── DietRepo / StatsRepo / ProfileRepo / MaintenanceRepo
   │
   ▼
SQLite（仅结构化字段，无 BLOB 音频）
```

- 页面的**每一个数字**都能在 §3 表里找到来源；找不到的，**不许渲染**。
- 页面**不得**自行聚合、自行排序、自行算分（`API-00` §1 规则 3）。
- 占位开发：B 的数据库就绪前，C 用 `FakeRepo`（`PLAN-00` §4「占位数据解耦」），就绪后切 `RealRepo`，**页面代码不改**。

## 6. 文案红线（FF-25，**UI 文案与 PPT 都适用**）

| ❌ 禁止 | ✅ 改为 |
|---|---|
| 零操作 / 记录成本降为零 | **零录入操作**；把逐条记录的成本降为**一次开关**的成本 |
| 完全无感 | **检测期间无感；检测由用户发起** |
| 准确识别所有食物 | **识别典型食物类别** |
| 我们可以测热量 | 营养与热量来自**知识库 + 标准份量估算**，UI 明确标注「估算」 |
| 2 秒内出结果 | 约 **4–5 秒**给出确认结果 |

机械验收：`rg -n "零操作|完全无感|识别所有食物|2 秒内出结果" lib/` 命中数必须为 **0**（各 `U-*` SPEC 的 §7 已写入该判据）。

## 7. 无障碍（写进每个 `U-*` SPEC 的 §8）

| 要求 | 说明 |
|---|---|
| 语义标签 | 所有交互元素须有 `Semantics` 标签，图标按钮必须有 `label` |
| 图表文本等价物 | 四维雷达图与趋势折线**必须**提供文本等价物（读屏可读的具体分值序列） |
| 对比度 | 文本与背景对比度 ≥ 4.5:1 |
| 触控目标 | 可点击区域 ≥ 48 × 48 dp |
| 动态字号 | 跟随系统字号缩放，不出现截断（`4.png`/`5.png` 旧稿的文本串位是反面教材） |
