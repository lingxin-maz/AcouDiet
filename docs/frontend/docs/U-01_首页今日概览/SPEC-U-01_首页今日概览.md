## 1. 目标与范围

### 1.1 一句话目标
作为 App 首屏，用一屏呈现「今天吃得怎么样」——今日健康评分与四维、估算能量参考、本周记录次数、今日记录列表，并以最醒目的入口发起 AI 检测。

### 1.2 范围内（In Scope）
| # | 元素 | 位置 |
|---|---|---|
| 1 | 今日健康评分 `totalScore` + 评级 `grade` | 主卡片 |
| 2 | 较昨日变化 `deltaVsYesterday` | 主卡片；`null`（无昨日数据）隐藏该行，**`0` 显示「持平」**（`ADR-10`） |
| 3 | 四维雷达（`regularity` / `structure` / `snack` / `speed`） | 主卡片右侧 |
| 4 | 估算能量参考（区间） | 次卡片 |
| 5 | 本周记录次数 | 次卡片 |
| 6 | 今日记录列表（`DietRecord[]`，最多显示 3 条 + 「查看全部」跳记录页） | 底部 |
| 7 | 「开始 AI 检测」主按钮（页面内**最醒目**元素） | 中部悬浮 |
| 8 | 右上角「我的」入口（非 Tab，见 `SPEC-00` §3.8 FF-23） | AppBar 右侧 |
| 9 | 首次进入的权限与隐私提示（仅一次，`SPEC-00` §3.9 FF-24） | 弹层 |
| 10 | 演示数据标识 | `DemoDataController.isDemoActive == true` 时显示 `演示数据`（`SPEC-A-04` §7 A-04-K3 冻结文案，四页共用同一常量） |

### 1.3 范围外（Out of Scope）——必须显式写出，防止实现方自由发挥
- **不做**「已摄入能量 1286/2000 kcal」式**目标进度条**：声学无法测重量，热量为知识库 × 标准份量估算。
- **不做**「食材多样性 N/12 种」（分母 12 不可能达到），**改为「本周记录次数」**。
- **不做**营养素（蛋白质/脂肪/碳水化合物/膳食纤维）任何展示或图表。
- **不做**历史记录页与报告页内容（分别属 `U-03` / `U-04`）；首页列表最多 3 条。
- **不做**饮食记录的编辑、删除、任意改类别（`X-02`）。
- **不做**任何网络请求、账号、云同步（`API-05` §1）。

## 2. 功能行为

### 2.1 触发与前置条件
| 项 | 内容 |
|---|---|
| 触发 | App 冷启动默认路由；从其他 Tab 返回首页时刷新 |
| 前置 | `AcouTheme` 已注入；SQLite 已打开（`D-01`/`D-02`）；评分服务可用（`A-01`） |
| 数据取出 | `StatsRepo.today()` / `StatsRepo.week()`（`D-03`，`API-03` §5）、`HealthScoreService.score(range)`（`A-01`，`API-04` §3）｜**ADR-23：评分窗口 = 最近 7 个本地日**（与 `week()` 同窗口），能量/次数/记录列表仍是「今天」 |
| 仓库 | D3–D7 用 `FakeRepo implements DietRepo, StatsRepo, ProfileRepo`（`API-03` §8）提供**契约内字段**的占位数据；B 就绪后换真实实现（`RealDietRepo` 等），页面代码不改（见 `PLAN-U-01` §3） |

### 2.2 主流程（编号步骤）
1. 进入首页 → 两个 Repo 调用与一次评分调用并行（`AsyncValue.loading` → `StateView(loading)`）。
2. 评分返回 → 渲染 `totalScore`（整数）、`grade`（良好/一般/需改善）、`deltaVsYesterday`（`↑12 分`；**为 `0` 时显示「持平」**，仅 `null`（上一等长窗口无可比数据）时**隐藏该行**，见 `ADR-10`）。**`ADR-23`**：窗口是最近 7 个本地日，因此 Δ 的口径是**上一等长窗口**（此前实现写死为"窗口前一天"，对 7 天窗口会拿一天比七天）；卡片标题为 **`近 7 天健康评分`**，Δ 行标签为 **`较上一周期`**。
3. 四维返回 → `FourDimRadar` 渲染 4 轴；四维明细可通过点击评分卡下钻（弹层显示 `label score/max`）。**`ADR-23`**：四维下方新增一行依据 `记录 N 次 · 零食 n 次 · 有咀嚼指标 m 条`（满分/空值都需要被解释）；「食物结构」在窗口记录数 < `minimumRecordsForDisplay`(3) 时**不可显示**（渲染 `--`），不把一条记录读成"结构完美"。
4. `StatsRepo.today()` 返回 → 估算能量参考渲染为 `estimatedKcal` 的 ±20% 区间 `约 1100–1400 kcal`；无记录时显示 `暂无数据`。
5. `StatsRepo.week()` 返回 → 渲染 `本周记录 {recordCount} 次`（窗口 = 最近 7 个设备本地日历日，含今日，`API-03` §5）；无数据时 `0 次`。
6. 今日记录取自 `TodaySummary.records` → 列表渲染 `RecordCard`（时间 + 食物名 + 图标）；空列表显示 `今天还没有记录`。
7. 用户点「开始 AI 检测」→ 跳 `U-02` 检测页（`push`，非 Tab 切换）。
8. 用户点右上角「我的」→ 跳 `U-05`。

### 2.3 状态与状态迁移

```dart
enum HomeStatus { idle, loading, ready, empty, error }   // 复用 SPEC-U-06 的 ViewStatus 语义
```

| 当前态 | 事件 | 下一态 | 说明 |
|---|---|---|---|
| `idle` | 首帧请求 | `loading` | 骨架屏，不显示 0 值 |
| `loading` | 3 个 Provider 全部返回 | `ready` | 任一为空按 §6 局部降级 |
| `loading` | 任一 Provider 抛错 | `error` | 整页 `StateView(error)` + 重试；**不用 0 兜底** |
| `ready` | 从检测页返回并新增记录 | `loading` → `ready` | 强制刷新3 个 Provider |
| `ready` | 清空全部数据（`D-05`） | `empty` | 评分 `--`、雷达空、列表空态 |

### 2.4 边界条件
- **评分窗口（`ADR-23`）**：四维评分取自**最近 7 个本地日**。理由：σ 需要同一餐段 ≥2 条样本、速度需要 ≥1 条带咀嚼指标的记录，单日窗口在结构上几乎永远无定义 —— 这正是"规律性/速度总是 `--`"的原因。能量、次数、记录列表仍是「今天」。
- 当天 0 条记录：评分**可能仍有值**（近 7 天内有记录时），能量 `暂无数据`、次数 `0 次`、列表 `今天还没有记录`；若近 7 天也无记录，则评分 `--`、雷达为空。
- 窗口内只有 1–2 条记录：「食物结构」样本不足 → 该维显示 `--`（不显示 30/30 满分）；「饮食规律性」σ 无定义 → 该维显示 `--`；总分显示 `--`。
- 跨零点停留：页面在前台跨越 00:00 时，返回前台须重算「今天」并刷新。
- 昨天无数据：`deltaVsYesterday` 为 `null` → 隐藏该行；**确为持平时值为 `0` → 显示「持平」，不得隐藏该行**（`ADR-10`、`API-04` §3）。**`ADR-23`**：这里比较的是**上一等长窗口**（7 天窗口 → 前 7 天），标签 `较上一周期`。
- 本周记录次数为 0：显示 `0 次`（非 `--`）。
- 存在 `source = 'demo'` 的记录（`A-04` Track 2 演示数据集）：记录条目与页面顶部须显示「演示数据」标识；**检测期间的「示例演示」标识**由 `patch.source == "inject"` 触发，属 `U-02`，本页不承担（`API-01` §3.2、`SPEC-A-04` §7）。

## 4. 数据契约

> 本表与**主方案 §3.4.1 UI 数据契约表**逐行一致；**表外字段不得出现在首页任何位置**（风险 R-19）。

| 展示元素 | 数据源 | 字段 | 单位/格式 | 无数据时 |
|---|---|---|---|---|
| 今日健康评分 | 评分引擎 `A-01` | `totalScore` | 整数 0–100 | `--` |
| 评级（良好/一般/需改善） | `A-01` | `grade` | 枚举 | `--` |
| 较昨日变化 | `A-01` | `deltaVsYesterday` | `↑12 分`；**0 显示「持平」**（`ADR-10`） | 隐藏该行（仅 `null` 时） |
| 四维雷达图 | `A-01` | `[regularity, structure, snack, speed]` | 各 0–满分 | 空雷达 |
| **估算能量参考** | 知识库 × 记录数 | `sum(kcal) ± 20%` | `约 1100–1400 kcal` | `暂无数据` |
| ~~食材多样性 8/12 种~~ → **本周记录次数** | `D-03` | `weekRecordCount` | `12 次` | `0 次` |
| 今日记录列表 | SQLite `D-03` | `DietRecord[]` | 时间 + 食物名 + 图标 | `今天还没有记录` |

**字段绑定说明（不改契约，只说明落地映射）**：
- `weekRecordCount` 绑定 `WeekSummary.recordCount`（同义，页面级显示名）。
- `sum(kcal) ± 20%` 绑定 `TodaySummary.estimatedKcal`，区间由 `AcouFormat.kcalRange` 生成。
- 四维绑定 `HealthScore.regularity / structure / snack / speed`（各为 `DimensionScore`）。
- 记录条目绑定 `DietRecord`（`eatenAtMs` / `classId` / `classLabel` / `attribute` / `confidence`）；`FoodInfo.portionDesc` 与 `portionKcal` 仅供条目第二行文案。

## 5. 参数与常量
- 评分四维与满分：`SPEC-00` §3.7 **FF-22**（总分 = 四维之和，0–100；**四维各自取整再求和**，见 `API-05` §6.2）。

- 页面数与「我的」非 Tab：`SPEC-00` §3.8 **FF-23**。

## 6. 异常与降级

| 异常 | 检测方式 | 处理 | 用户可见表现 |
|---|---|---|---|
| 评分服务失败 | `AcouDietError(code)` | 只降级评分卡 | 评分区 `--`，雷达空，其余区正常 |
| 本周汇总失败 | Provider `error` | 只降级次卡片 | `本周记录 -- 次` |
| 记录查询失败 | Provider `error` | 只降级列表 | 列表区 `暂时无法读取记录` + 重试 |
| 三区同时失败 | 3 个 Provider 均 `error` | 整页错误态 | `StateView(error)` + 重试按钮 |
| 数据库未就绪 | `openDatabase` 抛 `ACD-DB-001` | 整页错误态 | 「数据初始化失败，请重新打开」 |
| `classId` 越界（脏数据） | `byClassId` 抛 `ACD-KB-001` | 捕获后按占位渲染并记日志，**不整页失败** | 灰底图标 + `未知类别` |
| 记录数 > 3 | 列表长度判断 | 仅显示 3 条 | 底部「查看全部」跳记录页 |

## 8. 非功能约束

**内容硬规则（三条，与主方案 §3.4.1 一致）**
1. 热量数字**必须带份量描述与「估算」字样**；首页出现的任何 kcal 都不得是孤立数字。
2. 食物粒度**必须落在 6 类内**（`chips/cabbage/gummies/noodles/carrot/drink`）；禁止「全麦面条」「纯牛奶」「番茄」「鸡翅」等超出识别粒度的命名（ADR-19 起「面条」本身是正式类别，不再是禁用词）。
3. **无法从模型推导的营养素（蛋白质/脂肪/碳水化合物/膳食纤维）一律不得出现在 UI 上**。

| 类别 | 约束 |
|---|---|
| 首屏性能 | 冷启动到首帧可交互 ≤ 2 s（中端机，实测产出）；3 个 Provider 并行，禁止串行等待 |
| 刷新 | 从检测页返回必须刷新；刷新时保留旧值 + 顶部细进度条，不闪白屏 |
| 无障碍 | 评分卡语义标签形如「今日健康评分 85 分，评级良好，比昨天高 12 分」，持平时为「……，与昨天持平」；雷达提供文本等价物（四维逐项分数）；「开始 AI 检测」语义标签含动作词；点击区 ≥ 48×48 dp；颜色不单独承载语义 |
| 隐私 | 首页不申请任何权限、不发网络请求、不打点（FF-24）；首次进入的隐私提示仅说明「音频不落盘、无网络权限」 |
| 文案 | 遵守 FF-25：不写「零操作」「完全无感」「记录成本降为零」；如需表述，用「零录入操作」「检测期间无感，检测由用户发起」 |

- 营养素相关展示与进度条：**不做**（本文件 §8 硬规则 3）。

## 10. 开放问题
1. **首页「今天」的口径**：按设备本地时区的日历日（`API-00` §3.2）；跨时区/改系统时间的极端场景是否需要处理，待确认（建议不处理）。
2. **四维下钻的呈现形式**：弹层 vs 跳报告页；本 SPEC 采用弹层，需确认与 `U-04` 的下钻不重复。
3. **`FakeRepo` 占位数据集**：D3–D7 使用的占位数值需与 D8 真实数据、`A-04` 演示数据集统一为一套，避免再次出现「D-1 已知缺口」；具体数值由 `SPEC-A-04` 拍板。
4. ✅ **已关闭（依据 ADR-12）**：底栏 **4 Tab = 首页 / 检测 / 记录 / 报告**（`FF-23`）；「**我的**」为**首页右上角入口**（本页 §1.2 第 8 项、§3 的 `ProfilePage()` 路由），**不做独立 Tab**；自检面板（`M-04`）同样**不得成为第 5 个页面**（`SPEC-M-04` §10）。
