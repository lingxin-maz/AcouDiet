## 1. 目标与范围
### 1.1 一句话目标
提供 App 的「我的 / 设置」入口：本地档案（替代被裁剪的登录）、动态的坚持天数、静态成就展示、隐私声明、清空全部数据；并**如实告知**「数据仅存于本机，卸载即丢失」。v1.0 **不提供文件导出**，只提供一个**不落文件、不走网络**的「复制为文本」本地动作（`ADR-P4`）。

### 1.2 范围内（In Scope）
| # | 元素 | 说明 |
|---|---|---|
| 1 | 本地档案 | 昵称（可空）、固定本地头像资源、目标餐次、提醒开关、隐私横幅开关（`UserProfile`，`API-03` §6） |
| 2 | 「已坚持 N 天」**动态计数** | 非硬编码（`5.png`/`9.png` 的「7 天」须改）；数据源 = `StatsRepo.activeDays()`（`API-03` §5，`ADR-06` 修订 A-1）；该接口就绪前显示 `-- 天` |
| 3 | 成就**静态展示** | 仅展示固定徽章与文案，**无解锁逻辑、无进度**（`X-04`） |
| 4 | 入口列表 | 健康报告 → `U-04`；隐私设置；数据导出（**置灰 + 标「v1.1」**）；关于 |
| 5 | 隐私声明 | 无网络权限、音频不落盘、仅结构化数据本地保存（FF-24） |
| 6 | 清空全部数据 + 清除演示数据 | 清空 → `MaintenanceRepo.clearAllData()` + `clearTempAudio()`；`isDemoActive == true` 时**常驻**「清除演示数据」入口（`SPEC-A-04` §6），文案 `演示数据`（A-04-K3） |
| 7 | 数据可携带性告知 | 隐私声明**必须明确写**「数据仅存于本机，卸载即丢失」；v1.0 **不提供文件导出**（CSV / SAF 均不做）；**不提供**检测页历史列表入口（`X-05`） |
| 8 | 「复制为文本」按钮（`ADR-P4`） | 把当前记录序列化为**纯文本**写入**系统剪贴板**：**不走网络、不落文件、不外发**；是用户**显式发起的本地动作**；**不申请任何新权限**；**不改变 Manifest 的权限集合**（仍只有 `RECORD_AUDIO`，仍无 `INTERNET`） |
| 9 | **「本周健康数据概览」三宫格**（`ADR-24`） | 示意图 `9.png` 的三格：`总进食次数` / `平均咀嚼速度` / `零食次数`。三项**全部**读报告页「本周」的**同一个 7 个本地日窗口**：前两项是冻结的 `WeekSummary.recordCount` / `snackCount`，第三项是窗口平均咀嚼间隔（`StatsRepo.chewStats`，FF-22 速度维度的输入）经 `BehaviorAnalyzer.speedGradeFor` 映射出的档位词；**不新增任何指标**。降级契约：任一查询失败 → 三格**一起**显示 `--`（不出现"两格活着一格死了"）；窗口内没有咀嚼样本 → 该格显示 `无样本`，**不是** `正常` |

### 1.3 范围外（Out of Scope）——必须显式写出，防止实现方自由发挥
- **不做**登录 / 注册 / 账号体系（`X-01`），本页无任何账号相关 UI 与网络调用。
- **不做**成就解锁系统、进度条、解锁动画、成就弹窗（`X-04`）。
- **不做** CSV / 文件导出（`X-03`）；导出入口**只有置灰占位**，点击不产生任何**文件**出口。
- ~~**不做**剪贴板导出~~ → **改为实现**「复制为文本」按钮（`ADR-P4`，见 §1.2 第 8 项与 §10 开放问题 3）：它**只写系统剪贴板**，不引入任何文件写入路径。
- **不做** SAF 文件导出（`ADR-P4` 否决的选项 C）：SAF 会引入文件写入路径，与 `FF-24` 第 1/2 条的「不落盘」审查口径冲突，需额外论证；10 天窗口内不划算，留作 v1.1（`X-03`）。
- **不做**数据库加密设置（`API-05` §5.7：v1.0 不做）；**不做**模型热更新、检查更新、崩溃上报（`API-05` §1.2、§9.3 判据 4）。
- **不做**营养目标（热量/营养素）设置（声学无法测量，设置为无效功能）；**不做**主题/语言切换。

## 2. 功能行为
### 2.1 触发与前置条件
- 触发：首页右上角「我的」入口（**非独立 Tab**，FF-23）；或设计稿底栏入口（结构冲突见 §10）。
- 前置：`user_profile` 表已建（`D-01`/`D-02`）；本地档案可缺省创建。
- 数据取出：`profileProvider`（`SPEC-D-04`）、`activeDaysProvider`（`D-03` 聚合）、`demoDatasetProvider`（`A-04`，演示标识）。

### 2.2 主流程（编号步骤）
1. 进入「我的」→ 读取本地档案；无档案则按缺省值创建**一次性**本地档案（无账号、无网络）。
2. 渲染「已坚持 N 天」：`N` = 本地记录覆盖的**累计有记录天数**（动态，见 §2.4）；无记录时 `已坚持 0 天`。
3. 渲染成就区：静态徽章 + 固定文案，**不判断是否达成**，文案不得声称「已解锁」（`X-04`）。
4. 渲染入口列表：健康报告 → `U-04`；隐私设置 → 隐私声明；数据导出（置灰，标 `v1.1`，点击提示 `v1.0 暂不支持导出` —— 该提示**只针对文件导出**，数据带走走步骤 7 的「复制为文本」）；「复制为文本」按钮（`ADR-P4`）；关于。
5. 点「清空全部数据」→ 二次确认弹层（明确告知**不可恢复**、**卸载同样会丢失**）→ 调 `D-05` → 清空后回首页并刷新。
6. 清空完成后调用 `clearTempAudio`（FF-24 第 2 条）；隐私设置开关切换写回本地档案（开关不改变「无网络权限」这一事实）。
7. 点「复制为文本」→ 把当前记录按 §4 的准入规则序列化为**纯文本** → 写入**系统剪贴板** → 短暂提示「已复制到剪贴板」。全程**不走网络、不落文件、不外发**（`ADR-P4`，硬约束见 §2.4）。

### 2.3 状态与状态迁移
```dart
enum ProfileStatus { idle, loading, ready, empty, error }
enum ClearDataPhase { idle, confirming, clearing, done, failed }
```
| 当前态 | 事件 | 下一态 | 说明 |
|---|---|---|---|
| `idle` → `loading` | 进入页面 | `loading` | 读 `user_profile` 与天数聚合 |
| `loading` | 读取成功（有/无记录） | `ready` | 无记录仍显示 `已坚持 0 天`，**不进入空态**（本页始终有内容） |
| `loading` | 读取失败 | `error` | `StateView(error)` + 重试 |
| `ready` | 点「清空全部数据」 | `confirming` | 二次确认弹层；取消则回 `ready` 且数据不变 |
| `confirming` | 确认 | `clearing` | 按钮置忙、禁止重复点击 |
| `clearing` | `D-05` 成功 / 失败 | `done` / `failed` | 成功回首页并刷新、天数归 0；失败提示「清空失败，请重试」，**不谎报成功** |
| `ready` | 点「复制为文本」 | `ready` | **一次性本地动作**：写剪贴板成功后提示「已复制到剪贴板」，**不改变任何持久状态**；失败提示「复制失败，请重试」，**不得**改用文件落盘兜底（`ADR-P4`） |

### 2.4 边界条件
- **「已坚持 N 天」口径**：`N` = `StatsRepo.activeDays()`（`API-03` §5）= 库内**存在至少一条记录**的设备本地日历日数量（跨天去重，按设备本地时区日历日）。**不使用「连续天数」**，避免漏记一天即归零的负面体验；无记录 = `0 天`。
- 系统时间被向前调整：天数可能减少，属可接受（不做防篡改）。
- 清空数据后立即退出：不得残留 `cacheDir/audio_*`；下次启动再清一次（`API-01` §2.7）。
- 清空数据不影响已安装的模型与知识库（`assets/` 只读）。
- 演示数据集生效（`A-04` Track 2）：天数取 `StatsRepo.activeDays()` 的口径 —— **跨全部历史，不分 real/demo**（`API-03` §5、`ADR-06` 修订 A-1），页面不额外区分真实与演示行；页面照常显示「演示数据」标识。
- 档案字段为空：显示缺省昵称 `未设置昵称`，不崩溃。
- 版本号读 `pubspec.yaml`，不硬编码（`9.png` 的 `v1.0.0` 须与实际构建一致）。
- **「复制为文本」的四条硬约束（`ADR-P4`，必须逐条实现，不得放宽）**：① **不走网络** —— 不发起任何网络请求，`INTERNET` 权限仍**不申请**；② **不落文件** —— 不写 `filesDir` / `cacheDir` / 外部存储；③ **不外发** —— 不调分享、不调 `Intent`、不写 `MediaStore`；④ **不申请任何新权限** —— Manifest 的权限集合**不变**（仍只有 `RECORD_AUDIO`，仍无 `INTERNET`）。它是**用户显式发起的本地动作**，这正是它**不破坏**「无网络、音频不落盘」隐私主张的原因。
- **剪贴板载荷的字段准入**：序列化内容只允许取**契约表内**的记录页字段 `time` / `food` / `kcalRange` / `confidence` / `attribute`，**不得**含表外字段（风险 R-19）；单行热量一律带「估算」字样（§8 硬规则 1）。

## 4. 数据契约
### 4.1 与 UI 数据契约表的关系（**关键**）
`U-05` **不在**主方案 §3.4.1 UI 数据契约表的页面清单内（该表只覆盖首页 / 检测页 / 记录页 / 报告页）。因此：

| 类别 | 内容 | 准入规则 |
|---|---|---|
| A. 设置与本地档案 | 昵称、目标餐次、提醒开关、隐私横幅开关（`UserProfile`，`API-03` §6） | **非模型衍生数据**，不受契约表约束；字段集合以 `API-03` §6 / `SPEC-D-04` 为唯一真源，本页不得自行扩字段 |
| B. 记录派生计数 | `已坚持 N 天`（累计有记录天数） | 由 L4 提供，来源 `StatsRepo.activeDays()`（`API-03` §5，修订 A-1 新增、无参数、不随窗口变化）；**页面不得自行扫描全表**（`API-00` §1 规则 1） |
| C. 契约表外数值区块 | `9.png` 的「本周健康数据概览」（总进食次数 / 平均咀嚼速度 / 零食次数） | 🔴 **按 R-19 红线，v1.0 不实现**；如需保留须先走 `PLAN-C-03` 变更传播并入契约表（见 §10 开放问题 2） |
| D. 模型 / 评分衍生数据 | 评分、雷达、趋势、置信度 | **本页一律不展示**（那些是首页与报告页的职责） |
| E. 头像 | **不落库**：使用 APK 内固定本地资源 | `UserProfile` **没有**头像字段，UI 不得为此扩字段 |
| F. 剪贴板载荷（`ADR-P4`） | 「复制为文本」输出的纯文本：由**契约表内的记录页字段**（`time` / `food` / `kcalRange` / `confidence` / `attribute`）序列化 | **不新增 UI 字段、不扩字段集合**：载荷只搬运既有契约表字段，**不得**含表外字段（风险 R-19）；**不写库、不落文件、不走网络** |

### 4.3 文案契约（逐字）
| 场景 | 文案（不得改写） |
|---|---|
| 数据可携带性告知 | `你的记录仅保存在本机。卸载应用或更换手机后数据将无法找回，v1.0 不提供导出功能。` |
| 隐私声明要点 | `本应用不申请网络权限，无法上传任何数据；音频只在内存中处理，不写入存储。` |
| 清空确认弹层 | `将删除全部饮食记录与本地档案，且无法恢复。是否继续？` |
| 导出入口提示 / 成就区标题 | `数据导出将在 v1.1 提供` / `我的成就`（静态展示） |
| 「复制为文本」按钮与结果提示 | `复制为文本` / `已复制到剪贴板`（**不得**出现「导出文件」「分享到…」等措辞，避免与置灰的 v1.1 文件导出混淆） |
| 隐私声明（`ADR-P4` 强制告知） | `数据仅存于本机，卸载即丢失。` |

> **`ADR-P4` 后的口径澄清（逐字文案不改）**：「v1.0 不提供导出功能」一律读作**不提供文件导出**（CSV / SAF 均不做）；「复制为文本」是**只写系统剪贴板**的本地动作，**不落文件、不走网络**，因此不属于上表「导出」的含义，二者不矛盾。上表各条文案仍**逐字冻结**。

## 6. 异常与降级

| 异常 | 检测方式 | 处理 | 用户可见表现 |
|---|---|---|---|
| 档案读取失败 | `ACD-DB-*` | 只降级档案区 | 昵称 `未设置昵称`，其余入口可用 |
| 档案写入失败 | `ACD-DB-002` | 回滚开关状态 | 「设置未保存，请重试」 |
| 天数聚合失败 | Provider `error` | 只降级天数行 | `已坚持 -- 天` |
| 清空数据失败 | `ACD-DB-*` | 不清除任何部分（事务） | 「清空失败，请重试」——**不谎报成功** |
| 临时文件清理失败 | `ACD-IO-001` | 不重试，仅记日志 | 无提示；计入 `M-04` 自检面板并在 D9 前必须为 0 |
| 演示数据加载失败 | `ACD-DEMO-001` | 回退真实数据 | 无标识，功能不受影响 |
| 无记录状态 | 聚合返回 0 | 正常渲染 | `已坚持 0 天`（非空态） |
| 版本号读取失败 | 构建常量兜底 | 显示 `v1.0` | 不崩溃 |

## 8. 非功能约束
**内容硬规则（三条，与主方案 §3.4.1 一致）**
1. 热量数字**必须带份量描述与「估算」字样**；本页原则上不出现 kcal，若出现（如成就文案）不得是孤立数字。
2. 食物粒度**必须落在 6 类内**；成就文案若提及食物只用 FF-19 六类中文名。
3. **无法从模型推导的营养素（蛋白质/脂肪/碳水化合物/膳食纤维）一律不得出现在 UI 上**。

| 类别 | 约束 |
|---|---|
| 隐私（本页是最重要的合规界面） | 必须明确表述「无网络权限」与「音频不落盘」；清空数据一键可达（FF-24 第 7 条）；不得出现任何埋点/上报开关（因为不存在上报）；「复制为文本」（`ADR-P4`）是**用户显式发起的本地动作**——**不走网络、不落文件、不外发**，**不申请任何新权限**，Manifest 权限集合不变（FF-24 第 4/5 条） |
| 合规告知 | 数据可携带性缺口须如实告知（`API-05` §11）；**不得**自称「完全合规」或「数据可随时导出」 |
| 无障碍 | 每个入口行语义含动作（如「健康报告，查看周度饮食分析与建议」）；置灰导出入口朗读为「数据导出，v1.1 提供，当前不可用」；清空确认弹层焦点顺序「取消」→「确认」；开关控件有 `checked` 状态语义；点击区 ≥ 48×48 dp |
| 性能 / 安全 | 进入页面 ≤ 300 ms（本地读表 + 一次聚合）；清空为事务操作，失败不做部分删除；不写任何文件到 `filesDir` |

1. ✅ **已关闭（依据 ADR-06 修订 A-1）**：`StatsRepo` **新增** `Future<int> activeDays()`（`API-03` §5）—— 库内**存在至少一条记录**的设备本地日历日数量（**跨全部历史，不分 real/demo**）；**无参数、不随窗口变化**是刻意的，该文案的语义是累计天数。口径（累计、非连续，本 SPEC §2.4 已冻结）不变。**接口就绪前 UI 显示 `已坚持 -- 天`**，页面不得自行扫描全表（违反 `API-00` §1 规则 1）；**就绪后（D8）切换为真实值**。若工时不足，按 `API-03` §11.1 的降级顺序 `mealTimeSamples` → `activeDays`，此时本页长期显示 `已坚持 -- 天`。
2. 🔴 **`9.png` 的「本周健康数据概览」区块不在 UI 数据契约表内**（总进食次数 / 平均咀嚼速度 / 零食次数）。三项其实都有数据源（`D-03` / `A-01` / `P-07`），但**按 R-19 红线，表外字段不得上 UI**。两条出路需 A/B/C 拍板：① v1.0 **删除该区块**（本 SPEC 默认）；② 走 `PLAN-C-03` 变更传播把三项正式并入契约表后再实现。
3. ✅ **已关闭（`ADR-P4`，2026-09-10）**：**`API-05` §11「数据可携带性缺口」登记**（本节为该缺口的正式登记位置）。以下为原登记内容（**保留原行，供追溯**）与最终结论：
