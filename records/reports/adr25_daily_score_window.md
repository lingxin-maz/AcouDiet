# ADR-25 · 报告页「当日四维评分」恒无分数与评价

> 本文件是 `ADR-25` 的证据。裁定正文见 `docs/01_裁定记录ADR.md` 的 `ADR-25` 条目。
> 一句话：**一个为 7 天窗口设计的显示门槛被套到了 1 天窗口上**，于是单日总分与评价**恒定**为 `--`。

## 1. 用户原话

> 「报告那里当日四维评分的分数和评价都没有，修复这个BUG」

## 2. 先复现，再动手

新增诊断脚本 `tool/probe_daily_score.dart`：跑**真的** `ReportService.dailyScores` + **真的**
presenter 投影，逐日打印"哪一个显示门槛关着"。用的是 `FakeRepo.demoFixture()` —— 每天 4 条记录
（07:00 / 12:00 / 18:00 / 15:40 加餐），其中 3 条带咀嚼指标。**这是一天能做到的最好情况。**

### 修复前（实跑输出）

```
=== demoFixture (4 records/day, 3 with chew metrics) ===
day                 records   sigma   chewN   total   grade
2026-09-04          4         -       3       --      --
      rows: 饮食规律性=--  食物结构=30/30  零食控制=18/20  进食速度=15/20
2026-09-05          4         -       3       --      --
      rows: 饮食规律性=--  食物结构=30/30  零食控制=18/20  进食速度=15/20
...（7 天全部相同）

      rows: 饮食规律性=--  食物结构=30/30  零食控制=18/20  进食速度=15/20
```

**四条轴里三条有真实数字，而总分与评价是 `--`** —— 与用户描述逐字一致，而且**不是边界情况**。

### 修复后（实跑输出）

```
      rows: 饮食规律性=30/30  食物结构=30/30  零食控制=6/20   进食速度=15/20
```

## 3. 根因

```
ReportService.dailyScores:  scores.score(range: DateRange(dayStart, dayStart + 86400000))   ← 1 天
ScoreView.of 的显示门槛:     σ != null  &&  totalCount >= 3  &&  avgChewInterval != null
ScoreFormulas:               σ == null  →  规律性得 0 分（并记 null，让界面画 --）
```

- **σ 需要"同一餐段 ≥2 条样本"**（`API-03` §5.3）。一天通常是"一顿早饭 + 一顿午饭 + 一顿晚饭"，
  所以**单日 σ 在正常饮食下不可定义**；
- 于是 `ScoreView.of` 的门槛必然关着 → 总分与评价 `--`；
- 而 kernel 对 `σ == null` 记 **0 分** —— 这就是**同一根因的第二个症状**：趋势图「评分」线是一条
  系统性少掉整整 30 分规律性维度的低值曲线（demo 数据下恒为 63），看起来"像分数"，其实是缺了一维的和。

**这是口径错误，不是渲染缺陷。**

## 4. 裁定：日度数字一律取「以该日为最后一天的最近 7 个本地日」

| 理由 | 说明 |
|---|---|
| 唯一可行 | σ 需要多天，7 天窗口是**唯一**能让四维齐备、总分与评级成立的窗口 |
| 与首页**同一次计算** | 首页评分卡今天用的就是"最近 7 天"（`HomeNotifier.scoreWindowDays = 7`）。今天打开报告，「每日」的分与首页「近 7 天健康评分」**是同一个数**，`SPEC-C-05` 要的两页一致性自动成立 |
| 不发明公式、不做部分分 | 部分分正是 `ScoreView` 明确拒绝的"编造数字"（"A partial sum would be a fabricated number"） |

实现（两处调用点共用一个函数）：

```dart
static const int dailyScoreWindowDays = 7;

static DateRange scoreWindowFor(int dayStart) {
  final (start, end) = TimeUtil.lastLocalDays(dailyScoreWindowDays, nowMsOverride: dayStart);
  return DateRange(start, end);
}
```

## 5. 界面必须说出口径

一个覆盖 7 天的数字**不能被读成"那天的分"**，所以文案全部改到位：

| 位置 | 文案 |
|---|---|
| 每日卡标题 | `当日四维评分` → **`近 7 天评分（截至该日）`** |
| 每日列表标题 / 说明 | `每日评分` / 「每个有记录的日子一个评分（**该日及之前 6 天**）；无记录的日子不列出，点一天看该日明细」 |
| 卡片下注 | 「评分按『该日及之前 6 天』共 7 个本地日计算（σ 需同一餐段 ≥2 条样本，单日无法成立），因此卡片里那行『记录 N 次』是这 7 天的；下面的『当日汇总』才是该日自己的数据」 |
| 趋势图（评分轴） | 新增「评分口径：该日及之前 6 天（近 7 天）」 |

四维下钻里的 `windowDays` 本来就是可见证据（值 = 7）。

## 6. 已知边界（**说清楚，不含糊**）

- 序列中**最早的那一天**若其前 6 天没有任何记录，它的窗口只有它自己 → σ 仍不可定义 → **该日仍显示 `--`**。
  这是"还没有历史"，不是缺陷；连续记录满一周后即消失。
- 单日**自己的**个别轴仍可能是 `--`（例如该日没有带咀嚼指标的记录 → 进食速度 `--`），
  但总分会因为窗口齐备而显示。

## 7. 顺带修掉的乱码

`fake_repo.dart` 的 demo 指标里 `speedGrade: '姝ｅ父'`（应为 `'正常'`）—— 早先一次 PowerShell
管道编辑损坏 CJK 时漏掉的第二处，只在演示模式下显示。已修，并对 `lib/**/*.dart` 扫了一遍乱码特征
（`姝|锛|鈥|鎴|ｅ|锟…`）：**全仓只此一处，现已清零**。

## 9. 诚实边界

1. 这是**口径 bug**：修复改变了报告页日度数字的**含义**（从"当日隔离评分（实际上恒为 `--`）"变为
   "截至该日的近 7 天评分"）。
2. `trend()` 的评分线随之改变 —— 同一根因，属于修复而不是"顺带改行为"。
3. 若用户更希望"**严格只按当日、缺一轴就不给总分**"，那是另一个口径。本 ADR 记为**已否决**：
   它正是本次缺陷本身（单日 σ 不可定义 ⇒ 永远没有总分）。
